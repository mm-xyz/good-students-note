# ADR-2026-09-10-roomtone-insert — cutplan 插入留白：`## 🔇` ＋「乾淨室噪」的絕對 dBFS 判準

- 識別碼：ADR-2026-09-10-roomtone-insert
- 日期：2026-09-10
- 狀態：已採納
- 相關：ADR 0001（cutplan 是人審真相源）、ADR 0011（`## ➕` 補錄插入）、
  ADR 0015（podcast 剪輯 SOP）、ADR-2026-09-06-mixdown-audio-line（`audio=mixdown`）、
  ADR 0017（EP18 room-tone 鬼影）

## 脈絡

EP18 二剪，MM 的人審回饋要求兩處「留白」：開場白結束到進正題之間要 1–2 秒
緩衝，以及間奏後「回正題」那句不要馬上插進來。

cutplan 沒有任何插入靜音的指令。既有的五個結構行只能剪（`## ✂`）、疊音樂
（`## 🎵`）、插外部語音（`## ➕`）、標集錦與章節。`⏸` 停頓 block 的上限是
原長保留，做不出比錄音更長的空白。

**純數位靜音不能用。** 兩段人聲之間插一段數位零，會從有底噪突然掉到無底噪，
聽感就是「播放斷掉」——MM 在同一批回饋裡抱怨的 9:38 正是這個症狀。留白必須
是這場錄音自己的室噪。

第一次是手工做的：切一段 1.5s 室噪成 `pad_roomtone_1s5.wav`，用 `## ➕
gain=0` 插進去。**切錯了時間軸**——窗是用 `words.json`（`source.wav` 軸，
1224.8s）驗「這段沒有字」，檔案卻從 `.pertrack_bus.wav`（**已剪過的輸出軸**，
1103.7s）切出來。驗的跟切的不是同一段音訊，而且不會報錯。成品 0:21 出現 KIN
的小聲人聲，MM 聽出來。

事後量：壞窗 source 全頻 -39.4、人聲帶(300–3400Hz) -43.5、Mars 軌 max -30.1；
好窗 -63.5 / -69.1 / 三軌 max ≤ -50.8。當時擋不下來的原因是驗證方法本身不對
——只看了「RMS 剖面平不平坦」，而一段穩定的小聲人聲本來就是平的。

## 決策

### 1. 新結構行 `## 🔇 <秒數>  <說明>`

照文件順序插在成品的該位置（與 `## 🎵` / `## ➕` 同一套錨點規則）。不產生任何
中介檔：組 unit 時轉成既有的 `insert` unit（`path=source.wav`、`gain=0`、
`a`/`b`＝選定窗），複用已測過的 insert + atrim 路徑。

### 2. 室噪只准從 `source.wav` 取

**嚴禁 `.pertrack_bus.wav`。** 它是已剪過的輸出時間軸，而 `words.json` 與
cutplan 的所有座標都在 `source.wav` 原始軸上；混用＝「無字窗」會切到另一段
聲音，且靜默通過。這條寫進程式碼註解與 FAIL 訊息，不只寫在文件裡。

### 3. 「乾淨」＝五條判準全過（絕對 dBFS）

| # | 檢查 | 門檻 | 旋鈕 |
| - | --- | --- | --- |
| 1 | 來源是 `source.wav` | 硬性 | — |
| 2 | `words.json` 在窗前後各留白 | ≥ 0.3s | `--roomtone-word-margin` |
| 3 | 窗的全頻 mean_volume | ≤ -55 dBFS | `--roomtone-max-db` |
| 4 | 窗經 `highpass=300,lowpass=3400` 後 mean_volume | ≤ -60 dBFS | `--roomtone-voice-db` |
| 5 | **每一條分軌**（`tracks/*.WAV`）同時間碼 max_volume | ≤ -45 dBFS | `--roomtone-track-db` |

門檻可由 `## ⚙` 覆寫（cutplan 是參數真相源），優先序 config > CLI > 預設。

**為什麼是絕對值而不是相對本集底噪**（2026-09-10 MM 拍板）：相對門檻會讓
「合格」變成浮動標準，一集錄得特別小聲時會放行實際上不夠乾淨的窗。絕對值看
數字就知道過不過，代價是換錄音設備或增益後要重調一次門檻——那是明確、可察
覺的一次性成本，比靜默漂移好。

**第 5 條是決定性證據，也是這次事故真正該被擋下來的那一關**：混音裡聽得到的
小聲人聲，在他自己那支麥上一定很大聲。前四條全看混音，都可能被串音矇混過去。
`tracks/` 不存在（沒有分軌的集數）才跳過第 5 條，並在輸出印明「無分軌，跳過
分軌檢查」——**有分軌但某一支量不到，一律當不合格**：量不到代表我們對那支麥
當下有沒有人聲一無所知，不是代表它安靜。

### 4. 自動挑窗、印出用了哪一段

（2026-09-10 MM 拍板）render 自己用 `silencedetect` 掃 `source.wav` 找候選、
往內縮 0.3s、依人聲帶能量最低優先排序。同一次 render 只挑一次，所有 `## 🔇`
共用同一個窗。選定後印進 render.txt 存證：

```
[render] 🔇 選定室噪窗 ← source 8:44.92–8:45.92(全頻 -63.8 / 人聲帶 -69.7 / 分軌 max -50.8 dBFS)
```

### 5. 沒有合格窗 → FAIL，不准降級

列出最佳 3 個候選的實測值與各自沒過哪一條（含最吵的是哪一軌）。**嚴禁**退回
數位靜音、**嚴禁**自動放寬門檻。要求秒數超過最長合格窗也 FAIL，訊息講明
「最長只有 N 秒」——不用循環播放去湊長度。

## 後果

- 留白從「手工切檔 + `## ➕` 硬湊」變成一行標記，session 目錄不再累積 pad 檔。
- EP18 已定稿（v13）**不回頭遷移**：改 cutplan 會讓成品與節目單不一致，
  finalize_copy 會要求重 render，作廢已完成的定稿逐字稿。本功能從 EP19 起用。
- 換錄音設備或大幅調整輸入增益後，五條門檻要重新校一次。

## 驗證

- 新增 12 個回歸測試（`test_render_cut.py` 70 → 84），涵蓋解析、五條判準、
  邊界、FAIL 訊息、文件順序、config 覆寫。
- **Mutation 掃描**（把把關邏輯逐條弄壞，測試必須倒）：
  分軌 max ✅ 3 倒｜words 邊界 ✅ 1 倒｜室噪來源改 bus ✅ 4 倒｜人聲帶門檻 ✅ 2 倒。
  「有分軌但量不到就默認放行」這一刀第一輪**存活**（測試沒抓到），已補測試，
  重掃後 1 倒。
- 真音訊 dry-run（EP18）：自動選到 `source 8:44.92–8:45.92`，主線獨立用
  ffmpeg 複測全頻 -63.8 / 人聲帶 -69.7 / 三軌 max -57.1、-50.8、-58.3，
  與 render 印出的數字完全一致。
- FAIL 路徑實測：`--roomtone-voice-db -75` → FAIL 並指名「人聲帶 -69.7 >
  -75.0 dBFS」與最吵的 `2_Sarah.WAV`，沒有產生任何成品。
- `run_all.sh`：0 failed、0 skipped。
