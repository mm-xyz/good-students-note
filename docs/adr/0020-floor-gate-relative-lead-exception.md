# ADR 0020 — 底噪閘加「相對領先例外」，不放寬 hysteresis

- 識別碼：ADR-2026-08-14-726
- 日期：2026-08-14
- 狀態：已採納
- 相關：卡 #726（本卡）、卡 #677（診斷來源，880 筆歸屬不確定的成因分佈）、
  卡 #727（hysteresis/stable 邏輯，本卡明確不動）、2026-08-11 底噪閘原始
  commit（修 Sarah 4.7dB 搶麥破口）、`scripts/audio/pertrack_attrib.py`
  `owner_runs()`

## 脈絡

2026-08-11 MM 實聽抓到 EP16 38.5–39.0s「三軌都在底噪、沒人真的在講話，
Sarah 只因底噪高 4.7dB 就搶走所有權」，加了「三軌都低於各自校準 floor_db
就不換手」的底噪閘。方向正確，但是一刀切——閘只看「是否都低於絕對底噪」，
不看「即使都低於底噪，彼此之間差距有多大」。

#677 診斷把 880 筆「歸屬不確定」逐一分類成因，520 筆（59%、時長佔
68%）被歸為 `FLOOR_GATED`——這些 phrase 裡 leader 對第二名的 median 領先
其實有 18.6dB，遠超原始破口的 4.7dB。換句話說：閘把「講得比校準底噪還
小聲、但相對其他軌仍明顯是唯一在出聲的人」跟「真的沒人在講話」混為一談。

## 決策

在 `owner_runs()` 既有的底噪閘判定裡加一道相對領先例外：三軌都低於各自
`floor_db` 時，若 `leader - 第二名 ≥ FLOOR_BYPASS_LEAD_DB`（10.0dB，模組
頂部常數，可調），跳過這道閘，落下去走原有的 margin/hysteresis 判定
（跟平常換手邏輯完全一樣，不另開特殊分支）；領先不足 10dB 則維持原行為
（`cand = None`，不換手）。

10dB 門檻選擇：跟原始破口的 4.7dB 之間留 >5dB 緩衝帶，避免「剛好卡在
邊界」的雜訊抖動重新引入舊 bug；同時遠低於 #677 量到的 18.6dB median，
留出救回大部分 FLOOR_GATED 案例的空間。

**明確不動的範圍**：hysteresis/stable 時長邏輯（switch/stable 門檻本身、
scale-by-span 規則）是 #727 的事，本卡不碰；閘的 reason 文案（`split_
phrase` 裡的「歸屬不確定（三軌差距 <3dB）」等）是 #728 的事，本卡不碰。
豁免後仍然要撐滿 switch/stable 秒數才會真的換手——這是刻意的，相對領先
例外只拆掉「floor gate 的一票否決」，不代表「證據不足也能換手」。

## 量測（EP16 實資料，`scripts/tests` 之外另跑 #677 同款診斷重播，唯讀
`sessions/`，D2 production code 本身跑，非離線模擬）

| 指標 | Before | After |

| phrase 總數 | 2135 | 2135 |
| 歸屬不確定（筆數/占比） | 880（41.2%） | 708（33.2%） |
| 歸屬不確定（時長/占比） | 408.3s / 1730.4s（23.6%） | 328.7s / 1730.4s（19.0%） |
| 其中 `FLOOR_GATED` | 520 | 445 |
| 抽樣重疊比對，判定從 None→有 owner 的 phrase 數 | — | 80 |

**跟事前預期（41%→約 20%）有落差**，只降到 33.2%。根因：相對領先例外
只拆掉底噪閘的一票否決，被拆掉否決後仍要在原有 margin/hysteresis 規則下
撐滿 switch/stable 秒數才會真的換手——很多 `FLOOR_GATED` phrase 的高領先
只是短暫尖峰，撐不滿穩定時長，換手仍不成立，改記成 `NEVER_MARGIN` /
`FLICKER_UNSTABLE` 之類的其他不確定成因，不會消失，只是換了分類。這是
刻意的取捨（見上「明確不動的範圍」），不是實作缺陷；若要進一步壓低不確
定率，下一步是 #727 的 hysteresis 而非本卡的閘邏輯。

## 後果

- 好：D2 分軌歸屬不確定率 41.2%→33.2%（筆數）、23.6%→19.0%（時長），
  純函式改動、零依賴新套件，`scripts/tests/run_all.sh` 全綠。
- 好：門檻常數化在模組頂部（`FLOOR_BYPASS_LEAD_DB`），未來要調整緩衝帶
  不用碰邏輯本身。
- 代價/已知限制：改善幅度小於粗估（見上「量測」段落）——`FLOOR_GATED`
  的 520 筆裡只有 80 筆（15.4%）真的被救回，其餘仍卡在 hysteresis 的
  switch/stable 秒數門檻，改記成別的不確定成因。若要進一步壓低，下一步
  是 #727（hysteresis/stable 邏輯）而非本卡範圍。

## 同根因掃描

全 repo 搜尋 `owner_runs`/`floor_db`/`attr_floor`，只有
`scripts/audio/pertrack_attrib.py`（實作）與 `scripts/audio/
pertrack_blocks.py`（呼叫端，D2 唯一入口）兩處命中；`pertrack_blocks.py`
另外出現的 `floor` 是不相關的 D3 CFAR 門檻絕對下限（`floor = noise[i] +
args.floor_margin`），`render_cut.py` 的 `floor_db` 是 room-tone 合成鋪底
的量測結果，兩者都跟 D2 底噪閘無關，沒有發現邏輯拷貝。
