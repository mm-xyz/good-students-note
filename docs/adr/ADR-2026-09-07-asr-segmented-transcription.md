# ADR-2026-09-07-asr-segmented-transcription — 遠端 ASR 一律分段轉錄

- 識別碼：ADR-2026-09-07-asr-segmented-transcription
- 日期：2026-09-07
- 狀態：已採納
- 相關：ADR 0005（word timestamps 守衛鏈）、
  記憶 `whisper-prompt-style-transfers-to-output`（prompt 風格會傳染給輸出）

> 決策是 2026-09-07 MM 拍板、由轉錄線（good-student 線）實作於
> `transcribe_llmnode.py`；ADR 補寫於同日剪輯線收尾時，實測數字引自該線的紀錄與
> 其後續回報的對照實驗。

## 脈絡

`transcribe_llmnode.py` 原本一支音檔一次 whisper.cpp 跑完。whisper 的 `--prompt`
**只條件化第一個 30 秒窗口**，之後每個窗口拿前一段自己的輸出當脈絡。這代表 prompt
的書寫風格是靠「輸出→下一段脈絡」一路傳遞下去的，中途一旦滑掉就再也回不來。

實際後果是整份逐字稿零標點。批次轉 55 講實測 **21 講中招**，而且是非黑即白——
有標點的每 10–12 字一個，沒有的就是 0 個。這不是品質下降，是下游直接壞掉：短句切分
（`split_words_to_phrases`）靠標點與 ≥0.5s 停頓找切點，沒有標點就切不出 cue。

**觸發條件是 prompt 的書寫形式，不是長度。** 同日稍晚的對照實驗（同音檔、同模型、
只換 prompt，各跑兩次數字相同）：

| prompt | 標點密度 |
| :--- | :--- |
| 21 字純敘述 | 每 11.6 字一個 |
| 62 字敘述＋少量專名嵌在句中 | 每 11.8 字一個 |
| 147 字敘述＋一長串專名列舉 | **0 個** |

62 字版帶了專名照樣正常 ⇒ 壓掉標點的是**「列舉」這個形式**，不是專名本身、也不是
字數。原本的 context.txt 寫成頓號分隔的清單，55 講用的是同一份。

兩個機制都成立、不互斥：列舉形式的 prompt 把模型推進不標點模式（觸發），窗口滾動
把它一路帶到結束（延續）。同一份 prompt 只有 21/55 中招，說明是否觸發還跟素材本身
有關——**哪一講會中招事前無法預測**，這正是要在流程層兜底的理由。

## 決策

**分段轉錄是產物正確性的必要條件，不是效能優化。** 把音檔切成 ~7 分鐘的段落分別
轉錄，每段重新套用 `--prompt`，漂移就沒有累積的機會；段落 JSON 取回後把
`offsets`（毫秒）平移回全域時間軸再合併。

分段另外解掉一個獨立的問題：**長檔單次跑會 ssh 斷線**（106 分鐘那集就是這樣失敗的）。
就算標點問題完全靠 prompt 解決，分段仍然要留著。

搭配的必要條件寫在兩支轉錄腳本的 `--context` 讀取處：context.txt 一律 60 字上下的
自然敘述，專名嵌在句子裡，**不要寫成頓號分隔的清單**；`[:200]` 是硬截斷不是安全額度。

分段規則（`--segment-seconds` / `--max-segment-seconds`，預設 420/480）：
切 420s 一段；尾巴併進最後一段避免孤兒段；併完超過 480s 就對半切。

四個不變量是產物正確性，不是美觀問題，已用 `test_transcribe_llmnode.py` 鎖住
（0.1s–6000s 全掃）：

| 不變量 | 壞掉的後果 |
| :--- | :--- |
| 完整覆蓋 `[0, duration)` | 逐字稿少一段話 |
| 段落不重疊 | 同一句被轉錄兩次 |
| 每段 ≤ 上限 | 那段又會漂回不標點模式 |
| 無孤兒段（≥ 上限/2） | 只有幾秒的尾段轉出來多半是雜訊 |

### 沒有選的做法

- **只改 context.txt 的寫法**（60 字上下的自然敘述、專名嵌在句子裡）：**要做，但不能
  只做這個**。它拿掉觸發條件，是目前唯一直接證明有效的手段（見上表）；但同一份 prompt
  只有 21/55 中招，代表觸發與否還受素材影響，改完仍需驗收才知道有沒有成功。分段是
  流程層的兜底：就算某一段還是滑掉，也只壞那 7 分鐘而不是整份。
- **事後偵測零標點再重轉**：偵測得等整支跑完（2.75x realtime，一小時的講要 20 分鐘），
  而且沒有工具在做，靠人眼抽查。分段是把問題消滅在發生之前。

## 後果

- 短音檔（≤ 480s）行為不變，仍是單段一次跑完，不會多付 ssh + whisper 啟動成本。
- 段落邊界切在固定秒數上，不對齊字界：跨邊界的字可能在兩段都被切壞。以 7 分鐘一段
  計，一支一小時的材料約 8 個邊界，代價可接受；要更保險得做重疊窗口＋去重，目前沒做。
- 遠端逐段指令用 `;` 串接、whisper 輸出丟 `/dev/null`，單段失敗不會中止整批，靠取回
  階段的「第 N 段沒有 JSON」偵測。診斷訊息因此只知道哪一段失敗、不知道為什麼。
- ⚠️ **驗收一律看標點密度**，不要只看有沒有出 SRT。零標點時 cue 數、總字數、時間軸
  單調性、簡繁轉換全部正常，只有標點密度會暴露（正常中文每 10–40 字一個）。
- ⚠️ `batch_llmnode.sh` 是 resume-safe 的（`transcript.srt` 非空就跳過）。**已經產出的
  零標點逐字稿不會自動重轉**，要重跑得先刪掉那些 `transcript.srt`。
