# ADR-2026-10-03-keep-cue-level-block-granularity — cutplan 維持短句級 block，不改「一口氣一列」

- 識別碼：ADR-2026-10-03-keep-cue-level-block-granularity
- 日期：2026-10-03
- 狀態：已採納
- 相關：卡 #1077；2026-07-28「一行一句」（`cutplan.py:364`）、2026-08-11「每秒一個 block」（`srt_utils.py:137`）

## 脈絡

MM 反映 EP22「斷句都怪怪的」。兩份獨立流程審查（codex gpt-5.6-sol、fresh opus）都建議把 cutplan 一列從 whisper 短句 cue 改成較大的語意單位（同講者連續講到真停頓 ≥0.6s／句末標點／累積 12s 才斷，附和聲折疊成註記），估計人審列數降到每分鐘 12–17 列。

這個方向與前兩次拍板相反，所以先做 A/B 給 MM 手機實測：EP22 原始時間 29:30–34:30，同一段兩版 cutplan，文字逐字相同只差斷法。

| | A 現行 | B 一口氣 |
| :--- | ---: | ---: |
| 列數 | 165 | 59 |
| 每分鐘 | 33.0 | 11.8 |
| 中位時長 | 1.44s | 3.12s |
| 列尾停在虛詞 | 13.9% | 13.6% |

## 決策

**維持 A：短句級 block。** 不實作「一口氣一列」的合併。

## 後果

- 列數多是既定代價；精剪仍靠勾選＋刪除線兩種粒度並用。
- 兩份審查中與粒度無關的斷句問題仍然成立、不因本決策撤銷，可另案處理：
  - 講者歸屬逐字切、無平滑，在詞中換人（「山｜裡面」「金｜錢｜掛」）
  - 時間碼整秒截斷，看不出 0.1 秒的列
  - whisper 迴圈只掛警告仍預設保留；迴圈後標點崩潰
- A/B 素材與合併腳本保留在 Drive「AB測試_斷句_EP22_*」與 session scratchpad，日後要重評可直接重跑。
