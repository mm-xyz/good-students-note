# ADR-2026-11-13-1267 — to-md 的輸入範圍與首集實測順序：放棄直排書、網址走 Orca 瀏覽器、YouTube 字幕優先、講義區用 VLM 探測

- 識別碼：ADR-2026-11-13-1267
- 日期：2026-11-13（MM 拍板；寫入 2026-11-12 session 日誌的追加段）
- 狀態：已採納
- Lifov 卡：#1267（主卡）、#1328（P5b）、#1329（P6）、#1331（通用網頁 skill）、#616（discard）
- 相關：ADR-2026-11-12-1267（studio MCP 主決策）；`docs/design/2026-11-12_studio-mcp-architecture.md` §15–§21（全文）

## 背景

ADR-2026-11-12-1267 定了獨立 repo、搬家、skill 收成四顆。接著要回答兩個問題：`to-md` 這顆 skill 吃得下哪些輸入，以及三條線（知識、剪輯、短影音）的實作順序。實查現有管線後發現：直排書（#616）是唯一還沒做出來的輸入類型；文章網址與 YouTube 網址沒有既定做法；影片抽幀的講義區座標要人手動給；短影音線只在 EP15、EP16 跑過。

## 決策

1. **順序改成 P1 → P2 → P3 →（下週新一集實測）→ P4 → P5a → P5b → P7 →（MM 決定）P6。** 剪輯線用下週新的一集做實地驗收，這一集約六週後上架，P1–P3 目標 2026-12-06 前過驗收。P3 沒過就照舊流程在 good-students-note 剪，不拿正式的一集冒險。
2. **短影音線延後。** P1 搬家時**不搬 ai-reels**（修正 ADR-2026-11-12-1267 決定 2），ai-reels 維持現狀可用；`reel_prepare`、`reel_render` 保留設計不實作；P6 排最後，做不做等知識線與剪輯線上線後由 MM 決定。
3. **放棄直排書。** #616 discard；`input_probe` 偵測到直排就回 `GATE_FAILED`；doc-vlm-to-md 的「直排要先轉橫排並人工確認」鐵律不帶進 `to-md`；`scripts/doc/extract.py` 裡的直排程式 P1 照搬不動，P7 再移除。
4. **Office 檔用到再做。** 不列 P5b 驗收；P5b 順手用本機的 `markitdown` 各試一個含表格的 Word 與含圖的簡報，只記錄不接進 `ingest`。圖說沿用影片線的 llm-node VLM；備案是 Gemini（走 agy，不走付費 API key）。
5. **文章網址走 Orca 瀏覽器直接讀**，不寫抓取程式也不做成 MCP 工具。開網頁是常用動作，獨立成 mars-cc 的通用 skill（#1331），`to-md` 遇到文章網址時呼叫它；#1331 沒做完前 P5b 的網址驗收項順延。
6. **YouTube 先抓字幕，不夠好才下載轉錄。** `input_probe` 回報有無上傳者字幕／自動字幕、語言、片長；有上傳者字幕直接用；只有自動字幕就先跑標點密度檢查，不過門檻才下載；內容要看畫面的一律下載走影片線。`scripts/lang/vtt_to_txt.py`、`dedup_to_srt.py` 從「不搬」改成「要搬」；需新裝 `yt-dlp`。
7. **影片抽幀前先抽樣 20 幀用 VLM 判斷有沒有固定講義區**（新腳本 `scripts/frames/probe_region.py`）。20 幀中至少 14 幀回報有講義區且邊界差距在 5% 內才取中位數當 `--region`；agent 看預覽圖確認再決定帶不帶；VLM 失敗就當沒有固定版面繼續，不擋管線。門檻值 P5b 用三支已知版面的影片校正。
8. **「不行」的輸入（Markdown、純圖片資料夾）不在這一案。** 要加就在 P5b 之後各開一張卡，接在 `ingest` 的副檔名分流上，不改架構。`input_probe` 對不支援的類型要明確回 `GATE_FAILED` 並列出支援清單。

## 取捨

| 項目 | 採用 | 沒採用 | 代價 |
| :--- | :--- | :--- | :--- |
| 直排書 | 放棄 | 純掃描直排書的 VLM 抄錄路線（#616） | P5a 兩條文件管線比較時，「直排轉橫排」不再算管線 A 的優勢 |
| 文章網址 | Orca 瀏覽器＋通用 skill | 另寫抓取程式或 MCP 工具 | 只有在 Orca 裡跑的 agent 做得到，排程與純命令列情境沒這條路 |
| YouTube | 字幕優先 | 一律下載轉錄 | 字幕路線拿不到畫面與逐字時間戳；自動字幕常沒標點，靠密度檢查把關 |
| 講義區 | VLM 多幀取中位數＋預覽圖確認 | 人手動給座標（現況）／直接信單一幀 | 多 2 小時實作；小模型的邊界座標不一定準，所以加兩道確認 |
| 短影音線 | 延後、ai-reels 不搬 | 三線一起搬 | 工具清單暫時 17 個；封存 session 可當短影音輸入的規則照留 |

## 理由

- 剪輯線是三條線裡最常跑的，先用一集真實內容驗收，比先把三條線都搬完更能發現問題；上架日離現在六週，時程不趕。
- 直排書只有大耕紫微系列用到，已做完的產物封存不受影響；為一個已經過去的需求維護一條 VLM 抄錄管線不划算。
- Orca 的命令列本身就有開頁、等待、取文字（2026-11-13 實查 `orca --help`），能吃到要登入與 JavaScript 產生的頁面；判斷哪一塊是內文是判斷工作，適合 skill 不適合工具。
- YouTube 上傳者字幕的品質好且幾秒就拿到，一小時影片的本地轉錄要十幾分鐘到數十分鐘；兩支處理自動字幕的確定性腳本早就在 repo 裡。
- 講義區偵測的目的是讓場景偵測不被講者走動與台標觸發；`extract.py` 已有 `--region`，缺的只是座標從哪來。

## 後果

- P1 搬家的去留表要更正兩處：ai-reels 不搬、`scripts/lang/` 的兩支字幕腳本要搬。
- P5b（#1328）的驗收多四條：不支援類型回 `GATE_FAILED`、文章網址只靠 skill 進 session、有上傳者字幕的影片走字幕路線產出非空且標點密度過門檻的 `cleaned.srt`、講義區探測用三支影片校正門檻。
- Office 檔與 Markdown 輸入沒有排程；有需求時另開卡。
