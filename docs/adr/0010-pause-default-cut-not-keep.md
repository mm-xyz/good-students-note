# ADR 0010 — 停頓預設剪掉：留白才是要標的例外

- **Status**: Accepted（2026-08-10 MM 拍板「max-pause 預設 1.5 → 0.9 — 同意」）
- **Date**: 2026-08-10
- **Related**: ADR 0005（word 保護鏈）、ADR 0007（G 列預設不選）

## Context

EP16 二剪，兩位共同主持人各自回報「這裡的空白怪怪的」：

| 位置 | 空白 | 為什麼人審沒攔下來 |
| :--- | :--- | :--- |
| 成品 26:03 | 3.4s（G0010） | G 列**沒勾**＝該剪掉，但 render 的 snap 把兩側邊界移到同一個靜音中點，剪除量 0 |
| 成品 18:28 | 1.38s | block 間隔 <2s，不會列成 G 列，cutplan 上**完全看不到**；又低於 max-pause 1.5s 沒被自動收緊 |
| 成品 12:00 | 1.3s（block 內字間） | 同樣看不見；whisper 把停頓吃進「任」字的時長（736.24–737.70，1.46s），word 保護判定「這裡有字」而放棄收緊 |

關鍵事實：**三處都是聽成品才發現的，沒有一處是在 cutplan 上看出來的。**

ADR 0007 讓 ≥2s 的空白可見、預設不選（＝剪掉），方向正確但只覆蓋了最上面
那一層。真正的問題是心智模型：cutplan 把「每個空白」攤開讓人逐條決定，但人
盯著 `⬜ 空白 1.4s` 這行字，判斷不出它聽起來像節奏還是像當機——1.38s 那個
被主持人形容成「我以為當掉」。用文字審停頓這件事本身不成立。

## Decision

把預設反過來：**剪掉停頓是常態，保留才是要標的例外。**

- `--max-pause` 預設 **1.5 → 0.9**（`cutplan.py` 產出的 ⚙ config 行、README
  參數表同步）。超過 0.9s 的停頓一律收緊到 `--pause-keep`（維持 0.6s）。
- G 列機制不動（ADR 0007）：**要保留的沉默用勾選撈回來**——醞釀、笑點前的
  停頓、情緒轉折，這些是人審真正判斷得出、也只有人判斷得出的東西。
- 自動收緊必然失效的情形（whisper 把停頓吃進字的時長）走 `## ✂ 起-迄`
  手動剪除，排在 word_guard 之後，人審說了算。

`pause_keep` 暫不動：先觀察 0.9 在整集的聽感，一次只改一個變因。

## Consequences

- 人審的決策量從「每個空白都要判斷」降到「只有想留的才動手」，而且留下來的
  那幾個決策，正好是人審在文字上判斷得出來的。
- 既有三集（EP15/16/17）的 cutplan ⚙ 都寫死了 `max-pause=1.5`，config 覆蓋
  CLI，所以**不受新預設影響**；要套用得逐集改 ⚙ 行後重出。
- 節奏可能變得過緊——若出現「話跟話之間沒有呼吸」，第一個該調的是
  `pause-keep`（0.6 往上），而不是把 max-pause 調回去。
