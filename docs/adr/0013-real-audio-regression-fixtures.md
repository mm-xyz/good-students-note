# ADR 0013 — 剪輯鏈的回歸測試改用真音訊 fixture，且必須通過紅燈驗證

- 日期：2026-08-10
- 狀態：已採納
- 相關：ADR 0005（words.json 防護鏈）、ADR 0010（停頓預設剪掉）、ADR 0024（mars-cc，
  個人資料與 fixture 隔離）

## 背景

2026-08-10 處理 EP16 三剪時，挖出三個影響過去每一集的 bug：

1. **字級對齊全錯** — `strike_removals` 的字元流從 `win[0]` 起算，但 `win` 前後都會多抓
   鄰接 block 的字，整條偏移 → 既有 143 處刪除線**全部**退回線性內插（B0024 偏 0.74s，
   會把「傳達給我的 partner」切成「par—」）。
2. **長靜音兩端 snap 會合** — 前後兩個 unit 的邊界 snap 到同一個靜音中點 → 剪除量 0，
   G 列沒勾（＝該剪）也剪不掉（EP16 26:39 那 3.4s 就是這樣留在成品裡，全片找回約 21s）。
3. **word 保護擋掉真停頓** — whisper 把停頓吃進字的時長（「任」佔 1.46s），自動收緊必然失效。

關鍵事實：**這三個全部躲過了當時的 38 項單元測試。** 那些測試（`test_render_cut.py`）
用假資料鎖時間區間運算，而這三個 bug 錯在「**算得對但對到錯的字**」——區間運算本身正確，
輸入的字元流／靜音／字時長對到了錯的位置。假資料驗不出這種錯，因為假資料是照著實作的
心智模型捏的，實作錯在哪，假資料就跟著錯在哪。

同一天的跨模型對照組也印證了這點：codex `gpt-5.6-sol` 獨立找到字級對齊 bug 的完整修法，
而我自己只修了一半（處理了字元流尾巴、沒處理頭部）——半套修法照樣讓所有既有測試全綠。

## 決策

**剪輯鏈的回歸防線改成「真音訊 fixture」，與假資料單元測試並存、各司其職。**

- `scripts/tests/fixtures/build_fixtures.py` 從真 session 擷取「踩過的坑」：音訊裁窗、
  words／silences／blocks 一併裁到窗內並平移到 0 起算，產出**能直接餵給
  `render_cut.py --dry-run` 的迷你 session**，外加 `expect.json`（`must_cut`／`must_keep`）。
- `scripts/tests/test_render_audio.py` 逐個 case 跑完整條剪輯鏈（snap → 字級精剪 →
  停頓收緊 → ✂ → 谷底 → word 保護），驗該剪的剪掉、不該碰的還在。EP16 六個坑＝case1~6。
- **每個 case 必須通過紅燈驗證才算數**：把對應修復逐個退回去，確認它真的變紅。
  已驗：字級對齊退回「從 `win[0]` 起算」→ case1 紅；長靜音 snap 退回「一律取中點」→ case6 紅；
  `## ✂` 移回 `word_guard` 之前 → case4 紅。case2/3/5 鎖同機制的其他表現，對上述 revert
  不敏感但擋得住未來動到這幾條路徑的改動——這件事**明寫在測試 docstring 裡**，不假裝六個都驗過。
- 斷言**只驗區間中段**（兩側各留 25% margin）：剪點兩側各有 40ms 的 pad／谷底微調，
  那是設計不是缺陷，卡死到毫秒會讓測試對無關的參數調整過敏。
- **fixture 音訊不進版控**（被 `.gitignore` 的 `*.wav` 擋住，一個 case 約 4.5MB）。
  實測沒有 wav 斷言照樣成立、bug 照樣抓得到，只少 `refine_boundaries` 的波形谷底路徑；
  **缺席時測試啟動要明講降級並附重建指令，不得靜默通過。**
- case 內容一律避開節目裡被剪掉的敏感段落（MM 2026-08-10：「字級對齊不挑內容，換一段
  同樣有英文詞邊界的就好」），所以 `case1_strike_alignment` 用 B0084 而不是實際踩坑的 B0024。

## 取捨

| | 假資料單元測試 | 真音訊 fixture（本決策） | 每次改動全片重出＋人耳聽 |
| :--- | :--- | :--- | :--- |
| 抓得到「算得對但對到錯的字」 | ❌ | ✅ | ✅ |
| 跑一次的成本 | 毫秒 | 秒級（跑 render dry-run） | ⚠️ 數十分鐘＋人 |
| 建立成本 | 低 | 中（要寫擷取器、標斷言） | 零 |
| 進得了版控 | ✅ | ⚠️ 音訊要排除，只進 words/silences/blocks | — |
| 個資／敏感內容風險 | 無 | ⚠️ 取自真節目，要挑段落 | 無 |
| 回歸能不能在合併前擋下 | 部分 | ✅ | ❌ 太晚 |

## 理由

**測試要跟 bug 的失效模式對齊。** 這條線的 bug 不長在算式裡，長在「索引對到誰」——
字元流的起點、靜音的中點、字的時長。這幾個量只有真的 words／silences／波形才有；
用假資料鎖它們，等於用實作的假設去驗實作。38 項全綠卻讓三個影響每一集的 bug 溜過去，
是這件事的硬證據，不是運氣。

**紅燈驗證是這個決策的核心，不是附加要求。** 一個從未紅過的回歸測試沒有被證明有效——
它可能斷言在一個永遠成立的東西上。fixture 建好當天就回本：抓到我自己在修 snap 時引入的
regression（長靜音貼近端沒做 word 保護，「那你先說」的「說」被切 0.3s）。

**音訊不進版控是權衡後的妥協，不是偷懶。** 一個 case 4.5MB、六個就是 27MB，而這個 repo
的 git 歷史已經因為媒體檔付過代價（mars-cc ADR 0029）。實測確認斷言在無 wav 時仍成立，
所以進版控的邊際價值只有一條波形路徑的覆蓋——不值那個永久的歷史體積。**但「降級要看得見」
不能省**：靜默降級的測試比沒有測試更危險，因為它會給出「已覆蓋」的假象。

**避開敏感段落**是 mars-cc ADR 0024 的直接套用：fixture 取自 MM 的真節目，被剪掉的段落
往往正是不該留下的內容。字級對齊這種機制不挑內容，換一段就好，成本近零。

## 後果

- 新踩的坑有固定去處：改 `build_fixtures.py` 的 `CASES` 加一格（窗、strike、斷言、why），
  測試自動長出一條。`why` 同時是失敗訊息與測試 docstring，不用另外寫說明。
- 新 clone 的 repo 預設跑在降級模式（無 wav），會看到警告。要完整覆蓋得手動跑
  `build_fixtures.py` 指向一個有音訊的 session——這是刻意的成本轉移。
- fixture 的 `expect.json` 是硬編碼的絕對時間，只對那一集有效；換集重建即可，不要手改數字。
- 假資料單元測試（`test_render_cut.py`）不退場：它跑得快、鎖的是純運算的邊界條件，
  兩層一起才完整。
