# ADR 撰寫慣例

## 識別碼規則（2026-08-15 起，卡 #673 跨 repo 統一）

新增 ADR 一律用識別碼 `ADR-YYYY-MM-DD-<卡號>`（日期＝ADR 定稿當天，卡號＝
對應的 Lifov 看板卡），**檔名就是識別碼本身**：`ADR-YYYY-MM-DD-<卡號>.md`。
不再序號遞增（`0001`、`0002`…）、不留佔位、合併分支時不需要人工改號。

- **舊序號檔（`0001`～）維持原樣，不回溯改名。** 只有實際撞號（同一個序號
  前綴對到多個檔案）才照本規則改名；沒撞號的舊檔留著，讀者看到某份 ADR
  是舊序號格式屬正常現象，不代表規則沒切換。
- **沒有對應卡號時**，用一個簡短的描述性 slug 取代卡號位置，例如
  `ADR-2026-08-14-collab-retro.md`（先例見 mars-cc `000_Agent/adr/`）。
- **同一天、同一張卡出現兩份以上決策**時，不要各自生成同識別碼的多個檔案
  （會撞號）——把後面的決策當作**追加章節**併進同一份
  `ADR-YYYY-MM-DD-<卡號>.md`，用 `## 一、…` `## 二、…` 分節，並在檔頭加一句
  「併卡說明」交代原始來歷（實例見 `ADR-2026-08-11-674.md`：同卡 #674 同日
  先後定案的兩份決策，後者明確標註「取代前者部分內容」，合併為一份）。
- **跨引用一律寫完整識別碼**（例如「見 ADR-2026-08-11-672」），不要只寫
  日期或只寫卡號；引用舊序號檔一樣寫完整檔名前綴（例如「見 ADR 0014」）。
- 檔案內文開頭仍維持既有格式（`# ADR-YYYY-MM-DD-<卡號> — 標題`、接著
  `- 識別碼：`／`- 日期：`／`- 狀態：`／`- Lifov 卡：`／`- 相關：` 幾行
  metadata），識別碼在標題與 metadata 各出現一次。

## 寫 ADR 前先跑機械檢查

```bash
bash docs/adr/check_adr_ids.sh
```

掃描 `docs/adr/` 內的重複識別碼／重複舊序號前綴，發現撞號立刻 `exit 1` 並
印出撞號清單。新增或改名 ADR 檔案後、commit 前跑一次；CI 或 pre-commit 要
接的話也是掛這支腳本。
