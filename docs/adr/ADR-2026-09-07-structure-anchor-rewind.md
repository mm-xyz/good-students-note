# ADR-2026-09-07-structure-anchor-rewind — 分軌線結構行錨點：文件回跳＝歸片尾

- 識別碼：ADR-2026-09-07-structure-anchor-rewind
- 日期：2026-09-07
- 狀態：已採納
- 相關：ADR 0001（cutplan 是人審真相源）、ADR 0015（podcast 剪輯 SOP）、
  ADR-2026-09-06-mixdown-audio-line（同一集的第三條路線）

## 脈絡

MM 聽 EP18 final_cut_v8 回報「結尾的串場跑到中間去了」。實測屬實：把片尾音樂
`ending_532_to many mind_M尾.wav` 對整支成品做正規化互相關，峰值落在 **8:54.1
（相關 0.953）**，而全片 18:47 —— 片尾音樂精準地卡在節目正中央，還在那裡撐開
一段 17 秒的音樂插曲。

分軌線的成品不是照文件順序播的：`render_cut.py` 會把逐軌勾選解成 atomic cell、
算出全域保留區間，再**重新合成**一份「範圍即 block」的節目單。合成時非 block
的結構行（`## 🎵` 音樂、`## 🎬` 集錦、`## 章節`）要找回自己的位置，規則是
「錨點＝它後面第一個逐軌 block 的來源時間」。

這條規則預設**文件順序＝時間順序**。EP18 的 cutplan 尾端有一段「低信心非詞彙
出聲候選 111 筆」的 `<details>` 折疊附錄，回頭重列 0:41 起的早期 block；而
`## 🎵 ending` 排在附錄**之前**（它在正片最後一句 20:23 之後，位置本身是對的）。
於是片尾音樂錨到附錄首筆 `MR0018 [0:41]`，時間軸整個往回跳，音樂被安置到中段。

錨點取的是「後面第一個 block」，附錄裡的 block 全部沒勾也照樣當錨點——不保留
的內容決定了保留內容的排版。

## 決策

錨點規則加一條守衛：**逐軌 block 的來源時間一旦比「目前為止的最大時間」還早，
就是離開時間軸了**，此時待錨的結構行一律改錨到片尾（`inf`），並印警告。

比的是**最大值不是上一筆**：附錄自己內部是遞增的（0:41 → 2:19 → …），只比相鄰
兩筆的話，在附錄第二筆就會誤以為回到正軌。

錨點計算從 `main()` 抽成模組層的 `structure_anchors(program, tk_prefix)` 純函式，
回傳 `(anchors, rewinds)`，警告文字留在呼叫端。抽出來是為了能寫回歸測試——原本
埋在 main() 中段，只能靠端對端 dry-run 間接覆蓋。

### 沒有選的做法

- **把 `## 🎵 ending` 搬到 `</details>` 之後**：改的是 MM 的人審檔，而且 cutplan
  裡的位置本來就是對的（正片最後一句之後）。用挪動人審檔來遷就程式的假設，下一集
  重生成 cutplan 就會再犯一次。
- **錨點只認勾選的 block**：對 EP18 有效（附錄全沒勾），但 MM 從附錄「撈回來」勾
  任何一筆，bug 就原樣復發——那正是附錄存在的目的。

## 後果

- 波及範圍：`## 🎵 ending` 是在 2026-09-04 加進 cutplan 的，之後的分軌線出片
  **final_cut_v7、v8 兩版**片尾音樂都在中間。v6 以前沒有 ending 行，不受影響。
- 混音線不受影響：那條線照文件順序排，附錄的 block 沒勾就不產生 speech unit，
  音樂自然落在片尾。
- 這是通則不是 EP18 特例：任何分軌線 cutplan 只要尾端有折疊附錄、又有結構行排在
  附錄之前，都會踩到。修在錨點規則上，之後的集數不必再注意順序。
- 留下的訊號：踩到回跳會印 `⚠ cutplan 在 <id>(mm:ss) 往回跳…改錨到片尾`。這行
  出現是正常的（EP18 每次都會印一次），它是「守衛有生效」的證據。
