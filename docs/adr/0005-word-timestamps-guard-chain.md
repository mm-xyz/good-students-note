# ADR 0005 — 剪點防護鏈以 words.json 為準，SRT 邊界不可信

- **Status**: Accepted（2026-07-28 EP15 兩起實剪事故後落地，`73f26a0`＋`559b244`）
- **Date**: 2026-07-29
- **Related**: ADR 0002（五道確定性平滑是本防護鏈的宿主）

## Context

EP15 實剪暴露兩個「時間戳不可信」的事故，各在真相源的不同層：

1. **whisper 字級時間戳 artifact**：一個「好」字橫跨 718.6–735.3s（16.6 秒），
   把 B0556–B0567 整段語音吞成一個字。word_guard 被假字騙，把兩側剪點各推到假字
   頭尾，成品出現 **17 秒重複音訊**。
2. **SRT block 邊界比實際語音短**：「我不會覺得這樣很可惜嗎」的 block 結束在 737.22s，
   但 words.json 顯示「嗎」到 737.64s 才結束——尾字「惜嗎」被切掉（MM 聽感回報
   11:42 句尾被拉掉）。

兩個事故方向相反：一個是字級資料錯、一個是句級資料短。共同教訓：**單一來源的時間戳
都不可全信，要交叉制衡**。

## Decision

render 端建立三道防護，全部確定性、零 LLM：

1. **異常字丟棄**：載入 words.json 時丟棄時長 >3s 的 word（沒有正常單詞會超過 3 秒），
   印警告讓人知道該區間退回無字級保護狀態。
2. **unit 邊界字級對齊（`extend_unit_edges`）**：每個 speech unit 的首/末 block，用
   words.json 反查首/尾字的真實時間，邊界**只向外擴、不內縮**，上限 0.8s——避免把
   MM 剪掉的相鄰內容吃回來。
3. **exact 邊界跳過外推**：對齊成功的邊界標 `start_exact`/`end_exact`，後續
   snap/谷底/word_guard 一律不得再推——否則 snap 會把已精確的剪點再吸到附近靜音
   中點，重演「把剪掉的字吃回來」（實測 737.64 被外推到 738.78、多收了「就是」「尤」）。

## Consequences

- 剪點優先序明確：**字級對齊 > 靜音吸附 > 谷底微調**；資料越精確的來源權限越高。
- 異常字丟棄後該區間沒有字級保護（EP15 的 718–735s），停頓收緊與 word_guard 在該區
  間退化為 RMS-only——可接受，但若未來常見，可考慮從 SRT block 文字合成近似字級
  時間戳補洞。
- >3s 門檻是經驗值（中文單詞/短語不會超過）；英文長句被 whisper 併成一個 "word" 的
  情況若出現，再視實例調整。
