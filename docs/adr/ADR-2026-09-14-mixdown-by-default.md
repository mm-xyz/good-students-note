# ADR-2026-09-14-mixdown-by-default — 一律預設合軌，分軌要明寫才走

- 識別碼：ADR-2026-09-14-mixdown-by-default
- 日期：2026-09-14
- 狀態：已採納
- 相關：ADR 0014（**本 ADR 取代它**）、ADR-2026-09-06-mixdown-audio-line、卡 #681

## 脈絡

MM 2026-09-14：「分軌線不太能用，每一線切合很怪」「應該就是建立好都預設合軌就好」。

這不是新結論，是第三次收斂到同一個地方：

1. **2026-09-06**（ADR-2026-09-06）：EP18 出到 v7，MM 聽完說「分軌的品質不是很
   理想」，於是有了 `audio=mixdown`——剪輯決定照分軌人審跑，但音源改用合軌。
2. **2026-09-11**：EP19-0 直接走 `line=mixdown`，連決定層都不碰分軌。
3. **2026-09-14**：擱置卡 #681（分軌線降底噪）——接縫沒解決之前，降底噪是在優化
   一條不會被用的路線。

ADR 0014 的「素材決定路線，不是人選路線」在當時是對的直覺：有分軌就用分軌，資訊
比較多。但它假設了「分軌線的輸出品質至少不比合軌差」，而實測三次都不成立。

分軌線的成品不是原始音訊，是 `pertrack_render.mix_ranges()` 現場合出來的 speech
bus：三軌各自 gate、量 static gain 拉齊 LUFS、互相關對時、再鋪合成 room-tone。
這條鏈上任何一環沒調準都會比錄音機直接給的合軌難聽——**而合軌本來就存在**。

## 決策

`line` 沒明寫時一律 `mixdown`，不再從素材自動判斷。

### 有 `tracks/` 時仍然做的事

- **ingest**：錄音機只給分軌的場合，`source.wav` 就是 ingest 合出來的。停掉它等於
  沒有合軌可用。
- **`diarize --from-tracks`**：用分軌波形判斷「這句是誰說的」，零模型且比 pyannote
  準。它只影響講者標籤，不碰音質。

### 停掉的是 `pertrack_blocks`

逐軌節目單（`cutplan.pertrack.md`）才是分軌剪輯線的入口，也才是接縫的來源。

### 分軌線沒有退場

卡 #681 是 pending 不是丟棄。要走分軌：`precut.py --line pertrack`、cutplan 寫
`## ⚙ line=pertrack`。EP18 的既有分軌節目單明寫了，照跑不受影響。

**節目單是逐軌格式卻沒明寫 `line=pertrack` 直接 FAIL**，不靜默走合軌——那會讓
block id 整批對不上，錯誤訊息會指向完全無關的地方。

## 後果

- 好：新集數不會再因為「剛好有分軌」就走進一條 MM 不滿意的路線。
- 好：`cutplan.py prepare` 產出的 ⚙ 固定帶 `line=mixdown`，路線在節目單上一眼可見。
- 代價：分軌能做到的「留住時間、只把某一軌靜音」在合軌上做不到，那些串音會以原始
  音量回到成品（EP18 實測 176 個 cell、31.8 秒，占保留時間 2.9%）。串音特別重的
  集數仍可明寫切回分軌。
- 代價：分軌線的程式與 97 項測試繼續維護但不再是預設路徑，有 bit rot 風險。真要
  退場是另一個決定，需要先盤 ADR 0003 / ADR 0014 / PERTRACK_IMPL.md 的影響面。
