# ADR 0012 — 出片回流走零 token 一行指令，Drive↔session cutplan 用「語意對照」而非逐行 diff

- 日期：2026-08-10
- 狀態：已採納（MM 明講「零 token 剪片」是這條線的目標）
- 相關：ADR 0001（cutplan.md 是人審真相源）、ADR 0011（session 目錄與 Drive 同構）、
  harness 記憶 `feedback_podcast-cutplan-drive-copy`

## 背景

人審 cutplan 的**實際介面是 Google Drive 副本**（MM 在手機／平板上勾選、劃刪除線），
但 render 的真相源是 session 目錄那一份（ADR 0001）。兩份會分叉，而分叉的代價是靜默的：
2026-07-29 EP16 踩過一次——編輯全在 Drive、`render_cut.py` 吃到 session 的舊版，
出了一個「改了 cutplan 卻沒效果」的成品，人是聽成品才發現的。

在此之前，這段回流靠 agent 手做：讀兩份 cutplan、判斷差在哪、搬回 session、跑 render、
再把成品放回 Drive。三個問題：

1. **每跑一次就燒一次 token**，而重 render 是這條線的常態（EP16 十天內出了六版）。
2. **判斷差異這件事本身會出錯**，而且錯了不會有人發現——這正是 ADR 0001 防幻覺鏈
   在保護的那個位置，卻由 LLM 站崗。
3. `diff` 幫不上忙：cutplan 一個 block 一行、一行常常好幾百字，逐行 diff 的輸出
   是兩坨長文，人看不出「哪個 block 的勾選被翻掉了」。

## 決策

用 `scripts/audio/cut.py` 一行指令收掉整條回流，**零 LLM、零 token**：

```
python3 scripts/audio/cut.py --session sessions/<slug> [--check] [--yes] [--no-push]
```

1. **配對 Drive 資料夾**：靠 EP 編號比對（session slug 與 Drive 資料夾名字對不起來——
   EP15 一邊叫「前任」一邊叫「情緒管理」），配對結果寫進 session 的 `.drive_dir`，
   不用每次猜；配不出唯一解就明講並要求 `--drive` 指定，不亂挑。
2. **內容不同時列語意差異**，不是逐行 diff：哪些 block 的勾選翻轉、刪除線增減、
   `## ✂` 手動剪除、`## ⚙` 參數改了什麼。差異方向固定寫成「Drive → session」。
3. **由人選用哪一份出片**（預設指向 mtime 較新的那份，可選 Q 中止；`--yes` 或
   非互動環境才自動採預設）。不自動「新的蓋舊的」。
4. 選定版本先跑 `--dry-run` 印剪輯摘要給人看一眼；`--check` 可以只做到這步不出片。
5. render 出片，**檔名自動遞增 vN、不覆蓋既有成品**；完成後把 cutplan 與成品
   同步回 Drive（`--no-push` 可關），兩邊回到一致。

## 取捨

| | agent 手做回流 | 自動同步（新的蓋舊的） | 一行指令＋語意對照（本決策） |
| :--- | :--- | :--- | :--- |
| Token 成本 | ⚠️ 每版一次 | 零 | ✅ 零 |
| 分叉會不會被靜默吃掉 | ⚠️ 會（判斷錯無人知） | ⚠️ 會（另一邊的編輯直接消失） | ✅ 不會，先列差異再問 |
| 人看得懂差在哪 | 看 agent 轉述 | 看不到 | ✅ 勾選／刪除線／✂／⚙ 逐條 |
| 誤蓋成品的風險 | 視當次 prompt | 高 | ✅ vN 遞增不覆蓋 |
| 非互動（排程／unattended）可跑 | ⚠️ 要一個 session | 可 | ✅ `--yes` 走預設 |
| 實作與維護成本 | 零 | 低 | 中（語意 diff 要跟著 cutplan 語法長） |

## 理由

**這條回流是確定性的，不該用 LLM。** 讀兩個檔、比對結構化標記、選一份、跑腳本——
每一步都寫得出規則。把它交給 agent，付的是 token，換來的是一個會出錯又沒有驗證的環節；
寫成腳本，付的是一次實作成本，換來每次出片都一樣的行為。「零 token 剪片」不是省錢口號，
是**把人審之後的路徑全部變成可重現的機械步驟**，跟 ADR 0001 讓 cutplan 當真相源是同一個方向。

**語意對照而不是逐行 diff**，是因為這份文件的資訊不在「行」上，在勾選狀態、刪除線、
`✂`／`⚙` 這幾種標記上。逐行 diff 是通用工具，對這個檔案的訊噪比很差；語意 diff 只印
人真正要判斷的東西——代價是它跟 cutplan 語法耦合，新增節目項（如 ADR 0011 的 `## ➕`）
要同步補進 `semantic_diff`。這個代價是清楚的、可維護的，比「人看不懂差異所以隨便選一份」便宜。

**不自動選新的**：mtime 較新不等於內容較對——重跑管線會把 session 那份的 mtime 推新，
而人審的內容在 Drive。預設指過去、但要人按一下，是這個場景裡唯一安全的預設。

## 後果

- 出片變成一行指令，重 render 的邊際成本趨近於零——這反過來讓「多出幾版聽聽看」變得可行。
- `semantic_diff` 成為 cutplan 語法的第二個消費者（第一個是 `parse_program`）。
  改語法要同時想到它，否則差異會被靜默漏列——比 diff 壞掉更危險。
- Drive 路徑寫死在腳本裡（`DRIVE_ROOT`），換帳號或換雲端要改一處常數。
- `.drive_dir` 是 session 內的 memo 檔，人手動搬動 Drive 資料夾後要刪掉重配對。
