# ADR 0013 — podcast 剪輯線標準流程（SOP）

- 日期：2026-08-11
- 狀態：已採納
- 相關：ADR 0001（cutplan 是人審真相源）、ADR 0010（停頓預設剪掉）、
  ADR 0011（session 目錄與外部補錄）、ADR 0012（素材決定剪輯路線）

## 脈絡

這條線從 2026-07-29 首航到現在，流程一直是口耳相傳＋看 CLAUDE.md 的片段拼出來
的。EP16 這一輪出了 11 版，過程中反覆出現同一類問題：cutplan 有兩份不知道以誰
為準、改一次要重聽 30 分鐘才知道改對沒、參數散在 CLI 與 render.txt 之間。

2026-08-11 MM 把整條流程一次講清楚，本 ADR 把它固化。

## 決策

### 標準流程

```
1  丟音檔 & 改好名
2  初剪                          ← 全自動，不需要人介入
3  給 cutplan（集數資料夾根）
4  跑 script & draft 文案 & 生圖
5  create folder（版本目錄 vNN_<時戳>）
6  backup latest cutplan
7  依據最後一版開始剪
8  給 diff 片段 & draft 文案       ← 只聽改動處
9  再修 cutplan
10 再次跑 script
11 定稿
12 出文案，結束
```

7–10 是迴圈，跑到 MM 滿意為止。

### 四條配套規則

**(a) 「初剪」全自動。** 拿到音檔就一路跑到 cutplan 為止，不需要 MM 介入
（ingest → 轉錄 → 分軌歸屬／講者對齊 → cutplan）。MM 的第一個接觸點是第 3 步
拿到 cutplan，不是中間任何一個階段。

**(b) cutplan 住集數資料夾根，不進 `_meta/`。** session 端與 GDrive 端**同一個
位置**，不用記哪邊多一層。

反轉了 `cut.py` 原本「自動搬進 `_meta/`」的行為。原本的理由是「編輯中的
cutplan」要跟「某一版出片當下的快照」分開，避免人對著版本資料夾裡的快照改。
**這個顧慮現在的結構仍然滿足**——活的那份在集數根、快照在 `vNN_<時戳>/` 裡面，
`_meta/` 只是多一層。既有的 `_meta/cutplan.md` 自動搬回根。

**(c) 每次執行都要同步 GDrive 與 local 的 cutplan：詢問，預設擇新。**
`cut.py` 已有語意對照（哪些 block 勾選翻了、刪除線增減、`✂`/`⚙` 改了什麼）
與 mtime 比較，本 ADR 把「詢問＋預設擇新」定為必經步驟而非選用。
理由見 2026-07-29 事故：編輯全在 Drive、render 吃到 session 的舊版，出了一個
沒剪的成品。

**(d) render 參數與剪輯路線住 cutplan 的 `## ⚙` config，不住 render.txt。**

```
## ⚙ line=pertrack clip-gap=0.5 bgm-duck=0.15 max-pause=0.9 tempo=1.06
```

`line=pertrack|mixdown` 明寫就以它為準，沒寫才照 ADR 0012 自動偵測（保留
「素材決定路線」，又讓人能刻意指定，例如有分軌但想聽混音版對照）。寫了
`line=pertrack` 卻沒有 `tracks` 區直接 FAIL，不靜默退回混音。

**為什麼是 config 不是 render.txt**：cutplan 是參數真相源，它會跟著一起備份、
一起進版本目錄，而且**重跑時它是輸入不只是紀錄**——改 `line=` 就換線重出，
不必記指令參數。render.txt 是事後產物，容易跟實際跑的參數脫節。

### diff 片段（第 8 步）

`scripts/audio/diff_clips.py`：比對前後兩份 cutplan 的**人審決定**（勾選翻轉／
刪除線增減／新增段落），把每處變動對應到新成品的時間軸，各切一段 ±5 秒的
小片段。**刻意不產文檔**——MM 要的是耳朵驗收，不是再讀一份報告；檔名已帶成品
時間碼與 block id，要回頭查 cutplan 時夠用。

一輪人審從「重聽 30 分鐘」降到「聽幾十秒到幾分鐘」。

實作上踩到三個坑，都寫進測試：

1. **只比兩邊都有的 block id，會整批漏掉「新增一整段」**——EP16 的補錄是 16 個
   全新的 `S` block，原本完全不會出現在 diff 裡。改成新 id 且保留的也算變動；
   但新 id 佔比 >30% 判定為重切過，那種情況逐塊 diff 沒有意義，退回只比共有 id
   並在回報裡講明。
2. **補錄 block 的時間碼在補錄檔自己的時間軸上**（0 起算），不是源時間軸。直接
   換算會對出離譜位置（實測：補錄在成品 22:33，卻被切在 0:04）。改用它在節目單
   裡**前一個正片 block** 當錨點。
3. **用「點」而不是「區間」**，40 秒的補錄只會切出 10 秒接縫。改成區間合併。

## 後果

- 好：MM 的接觸點收斂成三個——拿 cutplan、聽 diff 片段、定稿。中間全自動。
- 好：cutplan 成為唯一需要同步的人審物件，位置兩邊一致。
- 代價：`## ⚙` config 現在混了數值型（`max-pause`）與字串型（`line`）參數，
  解析要兩套（既有的只收數值）。目前用 `params_raw` 另存一份原始字串處理。
- 代價：diff 片段依賴 `cut_map.json`，而它是 render 的產物、不進版控。要對
  「上上一版」做 diff 就得留著當時的 cut_map；目前只保證對得了最近一次。

## 尚未落地

- 第 2 步「初剪」還沒串成一鍵；現在仍是 ingest／transcribe／pertrack_blocks／
  cutplan prepare 分開跑。
- 第 4、8 步的「draft 文案 & 生圖」已有工具（`copy_prompt_build.py`、生圖
  prompt），但沒有跟本流程串起來。
- 第 5、6 步（建版本目錄、備份 cutplan）目前由 `cut.py` 做，尚未涵蓋分軌線。
