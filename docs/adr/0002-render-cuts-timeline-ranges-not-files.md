# ADR 0002 — render 剪的是共同時間軸上的範圍，不是檔案；節目結構＝文件行序

- **Status**: Accepted
- **Date**: 2026-07-27 ～ 2026-07-28（commits `5607ac3` 字級精剪、`a249e3b` 波形平滑、
  `35ad5a4` word 邊界保護、`30ebffd` 節目結構）
- **Related**: ADR 0001、CLAUDE.md 原則 6（確定性工作用工具，LLM 只做判斷）、原則 10

## Context

出片層（`render_cut.py`）要把人審後的 cutplan 變成成品 mp3。設計上有一個關鍵抽象選擇：
剪輯指令綁「檔案」（哪個音檔的哪段）還是綁「時間軸」（錄音共同時間軸上的哪些範圍）？
同時，節目結構（精華集錦冷開場、音樂床、章節）要住在哪：另一份結構檔，還是 cutplan 本身？

## Decision

**剪輯決策與音訊來源解耦：cutplan/render 操作的是共同時間軸上的時間範圍**。
音訊背後是 1 個檔還是 N 個檔，是 render 端的實作細節（此抽象是 ADR 0003 多軌決策的地基）。

render 全程零 LLM（原則 6），從 cutplan 算出 segments 後依序做：

1. **剪點 snap**：邊界落在 prosody.json 靜音段 ±0.4s 內 → 移到靜音中點。
2. **字級精剪**：`~~刪除線~~` 用 words.json 的 word 級時間軸精準剪掉那幾個字
   （字元流比對，對不上退回線性內插——寧可近似也不炸）。
3. **停頓收緊**：保留段內 >1.5s 的真停頓壓到 0.6s；先與 word 區間求差，
   不誤吃小聲字尾（EP15 0:49 事故的教訓）。
4. **波形平滑**：剪點滑到 ±90ms 內的能量谷底下刀；接縫 40ms acrossfade 三角交疊。
5. **word 邊界保護**（最後防線）：任何剪點落在字的時間區間內 → 推到字邊界外，絕不切在字中間。
6. **loudnorm**：EBU R128 動態 -16 LUFS，多人麥距/音量不同也拉齊。

**節目結構直接住 cutplan.md，播放順序＝文件行序**（commit `30ebffd`）：

- `## 🎬 精華集錦`：其下的 block 行是從正文**複製**來的（可跨時間軸、順序自訂、可重複出現），
  每段自帶淡入淡出（`--clip-fade`）。
- `## 🎵 <檔案> fadein=X fadeout=Y`：音樂床，與前後語音交叉淡化。
- 其他 `## 標題`：章節，render 換算新時間軸寫進 `chapters.txt`。
- 副產物 `cut_map.json`：新舊時間對照（之後剪 shorts/影片用）。

## Consequences

- 「播放順序＝文件行序」讓冷開場集錦、間奏、片尾曲全部用**排版**表達，不需要新檔案格式或 GUI。
- 時間軸抽象使 pipeline 對音訊來源數量中立——多軌支援不用重寫剪輯邏輯（見 ADR 0003）。
- 五道確定性平滑（snap/精剪/停頓/谷底/word guard）疊加後，剪點品質不依賴人工微調；
  代價是每道都有旋鈕（`--max-pause`/`--crossfade` 等），預設值要維持「安全可直接出片」。
- 集錦區塊可重複出現，因此驗證層的「block 集合一致」必須是集合語義而非計數語義（已如此實作）。
