# ADR 0014 — 有分軌走分軌線，只有混音軌走混音線

- 日期：2026-08-11
- 狀態：已採納
- 相關：ADR 0003（多軌 ingest）、ADR 0011（session 目錄與外部補錄）

## 脈絡

2026-08-11 為了解決「別人講話時的附和聲剪不掉」，新增了分軌剪輯線（三軌各自
gate → speech bus → 混音）。問題是：這條線要不要**取代**既有的混音線？

MM 拍板不取代：「以後可能還是會有只有混音軌的時候」。這不是假設性的顧慮——
**現在就有**：

- EP15《前任》是單軌錄的（當時還得靠 pyannote 聲紋分離），根本沒有分軌
- 來賓遠端連線、只拿得到一條合軌的舊素材、手機側錄，都是同一類

## 決策

**素材決定路線，不是人選路線**：

```
session 有 tracks/  → 分軌線（pertrack_render，三軌 gate → speech bus）
session 無 tracks/  → 混音線（從 source.wav atrim → concat）
```

`render_cut.py` 依 `cutplan.json` 有沒有 `tracks` 區自動分流，**不需要旗標、
不需要人選**。兩條線的人審介面同形（`- [x]` 勾選、`~~刪除線~~` 字級精剪），
所以素材換了，MM 的手感不換。

驗證（合併當下實測）：EP15（無 `tracks/`）在合併前後 `--dry-run` 輸出完全
一致——70 段、集錦 3 段、語音 34:25、原始 39:30。混音路徑一個位元沒動。

## 後果

- 好：舊素材與單軌情境永遠有路可走；分軌線是**加法**不是替換。
- 好：新增分軌能力不需要回頭改任何既有 session。
- 代價：兩條 render 路徑要一起維護。共用的剪點邏輯（snap／refine／word_guard／
  `enforce_monotonic`）修一次兩邊都受惠，但分軌特有的邏輯（atomic cells、
  activity mask、track offset）只有一邊有，測試要各自覆蓋。
- 代價：出片後光看檔案分不出走了哪條線。**`render.txt` 必須記錄本次走的路線**
  ——版本目錄名（如 `v08_…_分軌`）是人隨手取的標籤，不是機器寫的事實。

## 附帶發現（本次一併修掉）

- **剪點微調會讓相鄰段落重疊，同一段音訊播兩次**：`snap_boundaries`／
  `refine_boundaries`／`word_guard` 是逐 unit 各自算的，前段尾巴往後推、後段
  開頭往前拉就疊了。混音線 v7 有 1 處 0.48s，分軌線因剪點密集放大到 44 處
  共 15.6s。解法 `enforce_monotonic`（只夾往前推進的相鄰語音段，`🎬 集錦`
  的回頭重播不動），**兩條線一起受惠**。
  抓到它的不是任何數字檢查，是本地 whisper 重轉聽到同一句念了兩次。
- **三軌與 `source.wav` 差 219 樣本（4.97ms）**：所有 block 時間碼長在混音
  時間軸上，不補位移每個剪點都偏 5ms。`--track-offset auto` 用互相關量測，
  只採信 ρ≥0.55 的探測點。**這對每一集都要重量，不能沿用。**
